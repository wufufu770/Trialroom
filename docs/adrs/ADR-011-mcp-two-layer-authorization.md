# ADR-011 · MCP 双层强制权限模型

状态:已采纳(2026-10-27)
依据:11-final-plan §3.2(P0-4 裁决)/§3.11.3(G11 门禁)

## 背景

终稿第 68 行「最小 scope 是规范内建的能力」与第 72 行「真正的边界在服务端」自相矛盾(P0-4,
业主方裁决为"不改不能开工")。规范原文的准确语义是:TTL 等字段是**新鲜度提示而非权限证明**,
高风险工具每次 `tools/call` 都要重新鉴权。

## 决策

双层强制:

1. **`tools/list` 收敛只做 UX**(降 token、降误选),按令牌 scope 分片返回 —— 它不是安全边界,
   丢了它不丢安全;对应门禁断言是辅助性的(分片快照)。
2. **`tools/call` 是唯一授权强制点**:scope 匹配 + 资源绑定(座位/房主)双重判定,
   越权与不存在**同响应**(404 语义,防 10^6 房号存在性预言机)。
   这是 CI 主断言:每个工具 × 每个 scope 的正负例矩阵(G11 系列)。

## 附带决策

- `/mcp` 独立 token class(`mcp_tokens` 物理分表),与基座全局 token、平台 `api_tokens` 隔离
  (X-1 令牌混淆防护)。
- 推进权判 `room_seats.is_host`,不判 scope(scope 不是安全边界,S-03)。
- `room_code` 只作入座凭证:任何返回值不回显;`room_id`(rm_+22 位,≥128bit)是 capability。
- roots / sampling / logging 三能力显式不实现,收到即 `-32601`(SEP-2577 废弃窗口内不引入)。

## 后果

- 外部 agent 拿到低权令牌也**看不到**高权工具(UX 层),即使伪造调用也会在 tools/call 被拒
  且与"工具不存在"不可区分。
- 工具清单变更必须改冻结件 `config/mcp-tools.json` 并过 G11a,防止静默扩面。
